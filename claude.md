# Контекст проекта Competitive Programming

## Описание проекта

Эта директория используется для:
- Решения задач по competitive programming (Codeforces, AtCoder, etc.)
- Сбора собственной библиотеки (фреймворка) с алгоритмами и структурами данных
- Анализа и разбора неполучившихся задач

## Структура директорий

```
competitive/
├── library/               # Библиотека алгоритмов и структур данных (фреймворк)
│   ├── ex.cpp            # Примеры кода, шаблоны, реализации алгоритмов
│   └── ex2.cpp
│
├── solution/              # Рабочие файлы для решения задач
│   ├── cpp/
│   │   └── task.cpp      # Шаблон для C++ решений
│   └── py/
│       └── main.py       # Шаблон для Python решений
│
├── editorials/            # Разборы задач и тем (примеры)
│   └── examples/
│       ├── task_editorial_example.md        # Пример разбора задачи
│       └── topic_analysis_example/          # Пример разбора темы (Zettelkasten)
│           ├── index.md                     # Карта знаний
│           ├── 01_prime_factorization.md
│           ├── 02_trial_division.md
│           ├── 03_optimizations.md
│           ├── 04_applications.md
│           └── 05_related_topics.md
│
├── competitive_task.md    # Текущая задача для работы с Claude
└── claude.md              # Этот файл
```

**Примечание:** Итоговые разборы задач переносятся в отдельную директорию и не хранятся здесь. В `editorials/examples/` находятся только примеры форматов.

## Кастомные команды

### /solve_problem - Разбор задач

**Назначение:** Помощь в решении задачи или объяснение готового разбора.

**Как использовать:**
1. Добавьте ссылку на задачу в `competitive_task.md`
2. Вызовите `/solve_problem`
3. Claude автоматически определит режим работы

**Процесс работы:**

1. **Чтение задачи**
   - Claude читает `competitive_task.md`
   - Загружает условие задачи по ссылке
   - Определяет режим (есть разбор или нет)

2. **Режим объяснения** (когда разбор уже есть в файле)
   - Объясняет алгоритм понятным языком
   - Выделяет ключевые идеи
   - Показывает паттерны применения
   - Отвечает на уточняющие вопросы

3. **Режим помощи** (когда разбора нет)
   - Ведёт диалог, отвечает на вопросы
   - Направляет мышление правильными вопросами
   - НЕ даёт готовое решение сразу
   - Запоминает весь ход обсуждения

4. **Проверка усвоения**
   - Задаёт вопросы о решении
   - Проверяет понимание ключевых идей
   - Просит объяснить решение своими словами
   - На основе ответов дополняет итоговый разбор

5. **Создание итогового разбора**
   - Формирует разбор в формате `editorials/examples/task_editorial_example.md`
   - Включает:
     - Что было понято правильно
     - Пропущенные шаги и ошибки в мышлении
     - Правильное решение с ключевой мыслью
     - Признаки задач этого типа
     - Темы для изучения

**Выход:**
- Файл `editorials/[название_задачи].md` с полным разбором

**Пример использования:**

См. `editorials/examples/task_editorial_example.md` - пример итогового разбора задачи.

### /topic_analysis - Изучение тем

**Назначение:** Глубокое изучение любой темы в формате Zettelkasten (атомарные заметки со связями).

**Как использовать:**
1. Вызовите `/topic_analysis [название темы]`
2. Например: `/topic_analysis binary_search` или `/topic_analysis segment_tree`

**Процесс работы:**

1. **Разбиение темы на концепции**
   - Определяет ключевые концепции темы
   - Разбивает на атомарные (неделимые) идеи
   - Строит карту связей между концепциями

2. **Создание заметок в формате Zettelkasten**
   - Каждая заметка = одна атомарная идея
   - Формат каждой заметки:
     - Какую задачу решает
     - Суть (интуитивное объяснение)
     - Примеры с пошаговым разбором
     - Реализация (код C++/Python)
     - Сложность
     - Связи с другими заметками

3. **Создание index.md**
   - Карта всех заметок
   - Визуальное представление связей
   - Быстрая навигация по теме
   - Рекомендуемый порядок изучения

4. **Проверка усвоения**
   - Задаёт вопросы для проверки понимания
   - Просит решить простую задачу на тему
   - На основе ответов редактирует заметки:
     - Добавляет детали где непонятно
     - Упрощает объяснения
     - Добавляет примеры

5. **Дополнение библиотеки**
   - Добавляет реализацию в `library/[тема].cpp`
   - С комментариями и примером использования
   - Готовый код для использования в задачах

**Выход:**
- Папка `editorials/[название_темы]/` с заметками
- Файл `library/[название_темы].cpp` с реализацией

**Пример использования:**

См. `editorials/examples/topic_analysis_example/` - пример разбора темы "Разложение на простые множители":
- `index.md` - карта знаний с навигацией
- `01_prime_factorization.md` - основная концепция
- `02_trial_division.md` - алгоритм факторизации
- `03_optimizations.md` - оптимизации (до √n)
- `04_applications.md` - применение в задачах
- `05_related_topics.md` - связанные темы (НОД, НОК, делители)

**Преимущества формата Zettelkasten:**
- Каждую концепцию можно изучить отдельно
- Легко находить связи между темами
- Быстрое повторение нужных концепций
- Простое добавление новых знаний

## Формат разбора задач

Когда задача не получилась, используется следующий формат анализа:

### Шаблон разбора

```markdown
# Ссылка
[URL задачи]

---

# Теги
#тема1 #тема2

---

# Что я понял правильно

- Пункт 1
- Пункт 2
- ...

---

# Пропущенный шаг

### Ложное предположение

[Описание неверного предположения]

### Ошибка в мышлении

[Описание ошибки в логике решения]

Критический вопрос, который не был задан:
> _«[Вопрос]»_

---

# Правильное решение

1. Шаг 1
2. Шаг 2
   - детали
3. Шаг 3

Ключевая мысль:
> **[Основная идея решения]**

Признаки задачи (когда применять):
- Признак 1
- Признак 2

➡️ **[Вывод о применимости метода]**

---

# Что подтянуть

- Тема 1
- Тема 2
- Конкретные навыки
```

### Пример разбора

См. файл `editorials/examples/task_editorials/examples/task_editorial_example.md` — пример разбора задачи о нахождении максимального делителя числа `p`, не делящегося на `q`.

**Ключевые элементы разбора:**
1. **Ссылка** — URL задачи для быстрого доступа
2. **Теги** — категории задачи (теория чисел, DP, графы и т.д.)
3. **Что понял правильно** — корректные наблюдения и подходы
4. **Пропущенный шаг** — что было упущено, ложные предположения
5. **Правильное решение** — корректный алгоритм с ключевой мыслью
6. **Что подтянуть** — темы и навыки для изучения

## Работа с competitive_task.md

Файл `competitive_task.md` используется для работы над текущей задачей с Claude.

### Структура файла

```markdown
# Ссылка на задачу
[URL задачи на Codeforces/AtCoder/etc.]

---

# Разбор
[Текст разбора или пусто]
```

### Два режима работы

**Режим 1: Объяснение готового разбора**
- **Условие:** После `# Разбор` есть текст
- **Действие:** Claude объясняет решение, основываясь на тексте разбора
- **Цель:** Понять готовое решение, разобрать алгоритм

**Режим 2: Помощь в решении задачи**
- **Условие:** После `# Разбор` пусто (нет текста)
- **Действие:** Claude помогает решать задачу, отвечая на вопросы
- **Важно:**
  - Claude запоминает все обсуждения и вопросы-ответы
  - По итогу создаётся разбор в формате `editorials/examples/task_editorial_example.md`
  - Фиксируются: правильные наблюдения, ошибки, ключевые вопросы

### Процесс работы (Режим 2)

1. **Чтение задачи** — Claude читает условие по ссылке
2. **Диалог** — пользователь задаёт вопросы, Claude отвечает
3. **Фиксация мыслей** — Claude запоминает:
   - Какие наблюдения были правильными
   - Где произошла ошибка в логике
   - Какой вопрос был критическим
   - Как пришли к правильному решению
4. **Итоговый разбор** — по завершении создаётся разбор в формате `editorials/examples/task_editorial_example.md`

## Инструкции для Claude

### Работа с competitive_task.md

**При старте работы:**
1. Прочитать файл `competitive_task.md`
2. Прочитать условие задачи по ссылке (через WebFetch)
3. Определить режим работы:
   - Если есть текст после `# Разбор` → **режим объяснения**
   - Если пусто после `# Разбор` → **режим помощи**

**В режиме объяснения:**
- Разобрать предоставленное решение
- Объяснить алгоритм понятным языком
- Выделить ключевые идеи и паттерны
- Ответить на уточняющие вопросы

**В режиме помощи:**
- Отвечать на вопросы пользователя по задаче
- НЕ давать готовое решение сразу
- Направлять мышление правильными вопросами
- **Важно:** Запоминать ход диалога для итогового разбора:
  - Какие предположения были сделаны
  - Где произошла ошибка
  - Какие вопросы привели к решению
  - Правильные наблюдения пользователя

### Роль при разборе задач

Помогать анализировать неполучившиеся задачи, следуя формату выше:

1. **Выявить правильные наблюдения** — что было понято верно
2. **Найти ошибку в логике** — где произошёл сбой в мышлении
3. **Сформулировать ключевой вопрос** — который нужно было задать
4. **Объяснить правильное решение** — с акцентом на ключевую идею
5. **Определить паттерны** — признаки задач этого типа
6. **Рекомендовать темы** — что нужно подтянуть

### Принципы анализа

- Фокус на **процессе мышления**, а не только на коде
- Выделять **ключевые инсайты** и **критические вопросы**
- Показывать **признаки** задач данного типа (как их узнать)
- Структурировать мысли по разделам шаблона
- Быть конкретным: называть алгоритмы, техники, темы

### Работа с библиотекой

При добавлении кода в `library/`:
- Давать понятные имена файлам (например, `segment_tree.cpp`)
- Включать комментарии к реализации
- Указывать сложность алгоритмов
- Приводить примеры использования

## Рабочий процесс

### Основной процесс

1. **Начать работу над задачей**
   - Добавить ссылку на задачу в `competitive_task.md`
   - Оставить раздел `# Разбор` пустым

2. **Решение с помощью Claude**
   - Claude читает условие по ссылке
   - Обсуждать подходы, задавать вопросы
   - Писать код в `solution/cpp/task.cpp` или `solution/py/main.py`

3. **Если задача решена**
   - Очистить `competitive_task.md` для следующей задачи
   - При необходимости добавить новую технику в `library/`

4. **Если задача не получилась**
   - Добавить текст разбора в `competitive_task.md` после `# Разбор`
   - Claude объяснит решение
   - Создать итоговый разбор в формате `editorials/examples/task_editorial_example.md`
   - Перенести разбор в отдельную директорию

5. **Изучить и закрепить**
   - Добавить алгоритм/структуру в `library/`
   - Решить похожие задачи для закрепления

### Пример использования competitive_task.md

**Начало работы над задачей:**
```markdown
# Ссылка на задачу
https://codeforces.com/contest/123/problem/D

---

# Разбор

```

**После получения официального разбора:**
```markdown
# Ссылка на задачу
https://codeforces.com/contest/123/problem/D

---

# Разбор
Динамическое программирование на прямоугольном поле.
Ключевая идея: перебирать клетки в порядке возрастания суммы координат...
```
