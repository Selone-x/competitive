# Контекст проекта Competitive Programming

## Описание проекта

Эта директория используется для:
- Решения задач по competitive programming (Codeforces, AtCoder, etc.)
- Сбора собственной библиотеки (фреймворка) с алгоритмами и структурами данных
- Анализа и разбора неполучившихся задач

## Структура директорий

```
competitive/
├── library/          # Библиотека алгоритмов и структур данных (фреймворк)
│   ├── ex.cpp       # Примеры кода, шаблоны, реализации алгоритмов
│   └── ex2.cpp
│
├── solution/         # Рабочие файлы для решения задач
│   ├── cpp/
│   │   └── task.cpp  # Шаблон для C++ решений
│   └── py/
│       └── main.py   # Шаблон для Python решений
│
└── claude.md         # Этот файл
```

**Примечание:** Разборы задач в формате `.md` переносятся в отдельную директорию и не хранятся здесь.

## Формат разбора задач

Когда задача не получилась, используется следующий формат анализа:

### Шаблон разбора

```markdown
# Ссылка
[URL задачи]

---

# Теги
#тема1 #тема2

---

# Что я понял правильно

- Пункт 1
- Пункт 2
- ...

---

# Пропущенный шаг

### Ложное предположение

[Описание неверного предположения]

### Ошибка в мышлении

[Описание ошибки в логике решения]

Критический вопрос, который не был задан:
> _«[Вопрос]»_

---

# Правильное решение

1. Шаг 1
2. Шаг 2
   - детали
3. Шаг 3

Ключевая мысль:
> **[Основная идея решения]**

Признаки задачи (когда применять):
- Признак 1
- Признак 2

➡️ **[Вывод о применимости метода]**

---

# Что подтянуть

- Тема 1
- Тема 2
- Конкретные навыки
```

### Пример разбора

См. файл `test.md` — пример разбора задачи о нахождении максимального делителя числа `p`, не делящегося на `q`.

**Ключевые элементы разбора:**
1. **Ссылка** — URL задачи для быстрого доступа
2. **Теги** — категории задачи (теория чисел, DP, графы и т.д.)
3. **Что понял правильно** — корректные наблюдения и подходы
4. **Пропущенный шаг** — что было упущено, ложные предположения
5. **Правильное решение** — корректный алгоритм с ключевой мыслью
6. **Что подтянуть** — темы и навыки для изучения

## Инструкции для Claude

### Роль при разборе задач

Помогать анализировать неполучившиеся задачи, следуя формату выше:

1. **Выявить правильные наблюдения** — что было понято верно
2. **Найти ошибку в логике** — где произошёл сбой в мышлении
3. **Сформулировать ключевой вопрос** — который нужно было задать
4. **Объяснить правильное решение** — с акцентом на ключевую идею
5. **Определить паттерны** — признаки задач этого типа
6. **Рекомендовать темы** — что нужно подтянуть

### Принципы анализа

- Фокус на **процессе мышления**, а не только на коде
- Выделять **ключевые инсайты** и **критические вопросы**
- Показывать **признаки** задач данного типа (как их узнать)
- Структурировать мысли по разделам шаблона
- Быть конкретным: называть алгоритмы, техники, темы

### Работа с библиотекой

При добавлении кода в `library/`:
- Давать понятные имена файлам (например, `segment_tree.cpp`)
- Включать комментарии к реализации
- Указывать сложность алгоритмов
- Приводить примеры использования

## Рабочий процесс

1. **Решение задачи** — использовать файлы в `solution/cpp/` или `solution/py/`
2. **Если задача не получилась** — провести разбор по шаблону выше
3. **Изучить новую технику** — добавить реализацию в `library/`
4. **Повторить** — закрепить тему на похожих задачах
