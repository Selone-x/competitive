# Создание разборов задач

## Что такое editorial?

Editorial - это детальный разбор задачи с фокусом на **процесс мышления**, а не только на код.

**Формат:** `editorials/examples/task_editorial_example.md`

**Цель:** Понять **почему** задача не получилась и **как** мыслить в следующий раз.

## Структура editorial

### Шаблон

```markdown
# Ссылка
[URL задачи]

---

# Теги
#тема1 #тема2

---

# Что я понял правильно

- Пункт 1
- Пункт 2

---

# Пропущенный шаг

### Ложное предположение
[Описание неверного предположения]

### Ошибка в мышлении
[Описание ошибки в логике]

Критический вопрос:
> _«[Вопрос, который не был задан]»_

---

# Правильное решение

1. Шаг 1
2. Шаг 2

Ключевая мысль:
> **[Основная идея решения]**

Признаки задачи:
- Признак 1
- Признак 2

➡️ **[Вывод о применимости метода]**

---

# Что подтянуть

- Тема 1
- Тема 2
```

### Секции

**1. Ссылка** - URL задачи

**2. Теги** - категории (dp, greedy, graphs, etc.)

**3. Что понял правильно** - корректные наблюдения

**4. Пропущенный шаг** - критическая ошибка:
- Ложное предположение
- Ошибка в мышлении
- Критический вопрос

**5. Правильное решение** - корректный алгоритм:
- Пошаговое решение
- Ключевая мысль
- Признаки задач этого типа

**6. Что подтянуть** - темы для изучения

## Когда создавать?

**Обязательно:**
- Задача не получилась (WA, TLE, не додумался)
- Потрачено >30 минут без AC
- После изучения разбора

**Опционально:**
- После AC с подсказками
- Сложная задача (для закрепления)
- Новая техника (для запоминания)

**Не нужно:**
- Простые задачи (AC за 5-10 минут)
- Очевидные решения

## Фокус на мышлении

### НЕ просто код

**Плохо:**
```
# Правильное решение
вот код на C++:
for (int i = 0; i < n; i++) { ... }
```

**Хорошо:**
```
# Правильное решение
Алгоритм:
1. Отсортировать массив по возрастанию
2. Использовать два указателя (left, right)
3. Двигать указатели навстречу друг другу
4. Если сумма < target → left++
5. Если сумма > target → right--

Ключевая мысль:
> **Сортировка позволяет использовать два указателя
> для поиска пары за O(n) вместо O(n²)**
```

### Критический вопрос

**Самое важное:** Какой вопрос не был задан?

**Примеры:**
```
> _«За счёт чего именно число делится на q?»_
> _«Почему жадный подход даст оптимум?»_
> _«Какое свойство задачи позволяет использовать DP?»_
> _«Как избежать повторного подсчёта?»_
```

Этот вопрос - **ключ к решению**.

### Признаки задачи

**Как распознать похожие задачи?**

**Примеры:**
```
Признаки:
- Числа вида 10^18
- Условие p % q == 0
- Нужен максимальный делитель

➡️ **Почти наверняка факторизация**
```

```
Признаки:
- Движение по сетке
- Ограничения на переходы
- Небольшое число состояний (2-3)

➡️ **DP по позиции с состояниями**
```

## Примеры editorials

### Пример 1: Теория чисел

См. `editorials/examples/task_editorial_example.md`

**Задача:** Максимальный делитель p, не делящийся на q

**Ключевые моменты:**
- Ложное предположение: деление на делитель q уберёт делимость
- Ошибка: не учёл что делимость определяется степенями простых
- Критический вопрос: "За счёт чего p делится на q?"
- Решение: факторизация q, деление на каждый простой

### Пример 2: DP

**Задача:** Pipes (1234C)

**Что получилось:**
- Правильно определил DP по столбцам
- Верно выделил состояния (положение трубы)

**Пропущенный шаг:**
- Не учёл что переходы зависят от типа ячейки
- Критический вопрос: "Как тип ячейки влияет на переходы?"

**Решение:**
- DP с 2 состояниями (top/bottom)
- Переходы: тип "1" - только горизонтальные, тип "2" - любые

## Хранение editorials

### Структура

```
editorials/
├── examples/          # Примеры форматов
├── 1234D_editorial.md
├── 1444A_editorial.md
├── 2062C_editorial.md
└── geometry/          # Материалы по темам
    ├── index.md
    ├── 01_basics.md
    └── ...
```

### Именование

**Формат:** `{contest_id}{task_letter}_editorial.md`

**Примеры:**
- `1234D_editorial.md` - задача D из контеста 1234
- `1444A_editorial.md` - задача A из контеста 1444

### Поиск

Используй grep для поиска по тегам:

```bash
# Все editorials по DP
grep -r "#dp" editorials/

# Все editorials по graphs
grep -r "#graphs" editorials/
```

## Частые вопросы

### Нужно ли включать код в editorial?

**Нет!** Фокус на **мышлении**, а не коде.

**Можно:** Псевдокод или ключевые строки.

**Нельзя:** Полный листинг решения.

### Сколько времени на создание editorial?

**5-10 минут** если создаёт Claude автоматически.

**15-20 минут** если пишешь вручную.

### Как часто перечитывать editorials?

**Рекомендуется:**
- Через неделю после создания
- Перед контестом (похожие темы)
- При решении похожей задачи

### Можно ли редактировать editorial позже?

**Да!** Editorials - живые документы.

Можно:
- Добавить новые наблюдения
- Дополнить признаки задач
- Исправить ошибки
