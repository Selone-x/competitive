# Повторение набивашек из библиотеки (Library Drill)

**Проблема:** Спортсмены знают алгоритмы теоретически, но на соревновании теряют время, потому что не могут быстро набить реализацию из памяти — регулярной практики набивания библиотеки нет.

**Дата:** 2026-02-05
**Статус:** 🔲 Спланировано

---

## Контекст: формат файлов в library/

Каждый файл в `library/{lang}/{topic}/` имеет стандартную структуру с маркерами:

```cpp
// Имя алгоритма
// Ключевые слова: ...
// Сложность: O(...)
// Описание: ...

// ============ НАЧАЛО КОПИРУЕМОГО БЛОКА ============
// ... код без комментариев — это "эталон" ...
// ============ КОНЕЦ КОПИРУЕМОГО БЛОКА ============

// ============ РЕАЛИЗАЦИЯ С КОММЕНТАРИЯМИ ============
// ... тот же код, но с подробными комментариями ...
// ============ КОНЕЦ КОММЕНТИРОВАННОЙ ВЕРСИИ ============

// Примеры использования:
// ...
```

Drill использует именно эту структуру: КОПИРУЕМЫЙ БЛОК как эталон для сравнения, заголовочные комментарии (строки 1–4) как source metadata, КОММЕНТИРОВАННАЯ ВЕРСИЯ как опциональная подсказка.

## Сценарий использования

### Автоматический выбор темы (по слабым местам)

```
$ /coach drill
```

1. Claude смотрит в `core.json` → `knowledge_assessment.weak_topics` (например, `["dp", "graphs"]`).
2. Из слабых тем выбирает ту, для которой есть файл в `library/{preferred_language}/`.
   Например: `library/cpp/prime_factorization.cpp` — тема `number_theory`.
3. Если слабых тем с файлами в library нет — предлагает выбрать из доступных.

### Явный выбор темы

```
$ /coach drill prime_factorization
```

Claude берёт файл `library/cpp/prime_factorization.cpp` (или `py/` по `preferred_language`).

### Полный сценарий (пример: prime_factorization)

```
$ /coach drill prime_factorization

Описание: Находит разложение числа n на простые множители и их степени

Функции для набивания:
  - factorize(n)          → map<prime, power>
  - get_prime_divisors(n) → vector<prime>

  - Факторизация для числовой теории
  - Подсчёт количества делителей через формулу (a₁+1)×(a₂+1)×...

─────────────────────────────

```

4. Пользователь набивает код в `solution/cpp/task.cpp`:
```cpp
map<long long, int> factorize(long long n) {
    map<long long, int> factors;
    for (long long d = 2; d * d <= n; d++) {
        while (n % d == 0) {
            factors[d]++;
            n /= d;
        }
    }
    if (n > 1) factors[n]++;
    return factors;
}

vector<long long> get_prime_divisors(long long n) {
    vector<long long> primes;
    for (long long d = 2; d * d <= n; d++) {
        if (n % d == 0) {
            primes.push_back(d);
            while (n % d == 0) n /= d;
        }
    }
    if (n > 1) primes.push_back(n);
    return primes;
}
```

5. Пользователь пишет "готово". Claude читает `solution/cpp/task.cpp` и сравнивает семантически с КОПИРУЕМЫМ БЛОКОМ:


## Дизайн

### Парсинг файлов library/

Claude читает файл и извлекает три секции по маркерам:

| Секция | Маркеры | Использование |
|--------|---------|---------------|
| Metadata | Строки 1–4 (заголовочные комментарии) | Имя, ключевые слова, сложность, описание |
| Эталон | `НАЧАЛО КОПИРУЕМОГО БЛОКА` … `КОНЕЦ КОПИРУЕМОГО БЛОКА` | Сравнение с ответом пользователя |
| Подсказка | `РЕАЛИЗАЦИЯ С КОММЕНТАРИЯМИ` … `КОНЕЦ КОММЕНТИРОВАННОЙ ВЕРСИИ` | Опциональный hint (см. "Прогрессивность") |

### Семантическое сравнение

Сравнение — не diff по тексту, а по смыслу:
- **Функции:** есть ли все функции из эталона?
- **Логика:** алгоритм верный? (перебор до √n, обработка остатка и т.д.)
- **Edge cases:** обработка n=1, n=0 и т.п.
- **Сложность:** заявленная сложность O(√n) выполняется?

Итог: список ✅ / ⚠️ / ❌ и числовой `accuracy_score` от 0 до 1.

### Прогрессивность

| Ситуация | Поведение |
|----------|-----------|
| Первый drill по теме (нет записи в `drill_history`) | Claude предлагает: "Хочешь подсказку? (комментированная версия)" — пользователь решает сам |
| Повторный drill по той же теме | Подсказка не предлагается автоматически, но можно попросить явно |

### Точки входа

| Команда | Поведение |
|---------|-----------|
| `/coach drill` | Автовыбор из `weak_topics` → тема с файлом в library/ |
| `/coach drill {topic}` | Конкретная тема по имени файла |

## Расширения системы

### Новые поля в `stats.json`

```json

  {

    "topic": "prime_factorization",
    "language": "cpp",
    "functions_drilled": ["factorize", "get_prime_divisors", "count_divisors"],
    "accuracy_score": 1.0,
    "missed_parts": [],
    "used_hint": false
  }
]
```

Поле `drill_history` — новый массив в `stats.json`, не конфликтует с существующими полями.

### Что НЕ меняется

- **confidence в `core.json`** — drill не обновляет confidence напрямую. Это тренировка мышечной памяти, а не изучение новой темы. Уверенность растёт через learning и practice.
- **`core.json`** — не меняется вообще.
- **`codeforces_api.py`** — не задействован.
- **library/** — файлы только читаются, не пишутся.

## Интеграция с существующей системой

| Компонент | Что меняется | Как |
|-----------|--------------|-----|
| `library/{lang}/{topic}/` | Читается | Парсинг по существующим маркерам `НАЧАЛО/КОНЕЦ КОПИРУЕМОГО БЛОКА` |
| `stats.json` | +поле `drill_history` | Новый массив, не конфликтует |
| `SKILL.md` | +секция "Режим drill" | Аргумент `drill` / `drill {topic}` к команде `/coach` |
| `core.json` | не меняется | Drill не влияет на confidence |
| `codeforces_api.py` | не меняется | Drill — локальный режим |
