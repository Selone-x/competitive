# Работа с библиотекой алгоритмов

## Что такое библиотека?

Библиотека - это коллекция готовых реализаций алгоритмов и структур данных для быстрого копирования в контестах.

**Расположение:**
- `library/cpp/` - реализации на C++
- `library/py/` - реализации на Python

**Цель:** Быстро скопировать проверенный код в решение без набивания с нуля.

## Формат файлов

### Структура файла

```cpp
// [Название алгоритма]
// Ключевые слова: keyword1, keyword2, keyword3
// Сложность: O(...)
// Описание: краткое описание

// ============ НАЧАЛО КОПИРУЕМОГО БЛОКА ============
// Чистый код БЕЗ комментариев

struct SegmentTree {
    vector<int> tree;
    int n;

    SegmentTree(int size) : n(size), tree(4 * size) {}

    void update(int pos, int val) {
        // ...
    }

    int query(int l, int r) {
        // ...
    }
};

// ============ КОНЕЦ КОПИРУЕМОГО БЛОКА ============

// ============ РЕАЛИЗАЦИЯ С КОММЕНТАРИЯМИ ============
// Тот же код С подробными комментариями

struct SegmentTree {
    vector<int> tree;  // Дерево отрезков
    int n;             // Размер массива

    // Конструктор
    SegmentTree(int size) : n(size), tree(4 * size) {}

    // Обновление элемента
    void update(int pos, int val) {
        // ...
    }

    // Запрос на отрезке
    int query(int l, int r) {
        // ...
    }
};

// ============ КОНЕЦ КОММЕНТИРОВАННОЙ ВЕРСИИ ============

// Примеры использования
void example() {
    SegmentTree st(10);
    st.update(5, 100);
    cout << st.query(0, 9) << "\n";
}
```

### Два блока кода

**1. КОПИРУЕМЫЙ БЛОК** - для контеста
- Без комментариев (экономия времени)
- Готов к копированию целиком
- Минимум лишнего

**2. КОММЕНТИРОВАННАЯ ВЕРСИЯ** - для изучения
- С подробными комментариями
- Объяснения логики
- Для понимания как работает

### Метаданные

**В начале файла:**

```cpp
// Segment Tree (Дерево отрезков)
// Ключевые слова: segtree, range query, range update
// Сложность: O(log n) update, O(log n) query
// Описание: Структура для запросов и обновлений на отрезке
```

**Зачем:** Для быстрого поиска нужного алгоритма.

## Организация библиотеки

### Именование файлов

**Формат:** `{algorithm_name}.cpp`

**Примеры:**
- `segment_tree.cpp`
- `dijkstra.cpp`
- `prime_factorization.cpp`
- `suffix_array.cpp`

**Используй snake_case** (не CamelCase).

### Группировка (опционально)

Можно создать подпапки:

```
library/cpp/
├── graphs/
│   ├── dijkstra.cpp
│   ├── bellman_ford.cpp
│   └── floyd_warshall.cpp
├── data_structures/
│   ├── segment_tree.cpp
│   ├── fenwick_tree.cpp
│   └── dsu.cpp
└── strings/
    ├── kmp.cpp
    ├── z_function.cpp
    └── suffix_array.cpp
```

Но не обязательно - grep работает рекурсивно.

## Режим drill

**Drill использует библиотеку для тренировки.**

```
/coach drill segment_tree
```

**Что происходит:**
1. Читаются метаданные из `library/cpp/segment_tree.cpp`
2. Показываются (без кода!)
3. Ты набиваешь по памяти
4. Claude сравнивает с КОПИРУЕМЫМ БЛОКОМ
5. Даёт обратную связь

## Частые вопросы

### Нужно ли заполнять библиотеку сразу?

**Нет!** Заполняй постепенно.

После изучения темы → добавь реализацию.
После контеста → добавь что использовал.

**Со временем** библиотека заполнится естественно.

### Можно ли копировать из интернета?

**Да**, но:
- Убедись что понимаешь код
- Переформатируй в формат библиотеки
- Добавь комментарии
- Протестируй локально

**Лучше:** Реализуй сам после изучения.

### Как обновлять код в библиотеке?

**Если нашёл ошибку:**
1. Исправь в файле библиотеки
2. Обнови комментарии
3. Проверь на тестах

**Если нашёл оптимизацию:**
1. Добавь как новый вариант
2. Или замени старый код
3. Укажи в комментариях

### Нужно ли тестировать код из библиотеки?

**Обязательно перед контестом!**

Создай `test.cpp`:
```cpp
#include "library/cpp/segment_tree.cpp"

void test() {
    // Тесты
}
```

Проверь на edge cases.

### Можно ли хранить несколько вариантов?

**Да!**

**Пример:**
- `segment_tree_basic.cpp` - базовая версия
- `segment_tree_lazy.cpp` - с lazy propagation
- `segment_tree_persistent.cpp` - персистентная

### Как поддерживать библиотеку в актуальном состоянии?

**Регулярно:**
- После изучения темы → добавить код
- После контеста → проверить что использовал
- Раз в месяц → ревью всей библиотеки
- Перед контестом → drill по частым темам

---

**Собирай библиотеку постепенно - она станет твоим преимуществом на контестах!**
