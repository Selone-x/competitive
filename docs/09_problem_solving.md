# Работа с задачами через PROBLEM.md

## Что такое PROBLEM.md?

`solution/PROBLEM.md` - файл для работы над текущей задачей с Claude.

**Два режима работы:**
1. **Режим помощи** - решение задачи с консультацией
2. **Режим объяснения** - изучение готового разбора

## Структура файла

```markdown
# Ссылка на задачу
[URL задачи]

---

# Разбор
[Текст разбора или пусто]
```

### Пример 1: Режим помощи (разбор пустой)

```markdown
# Ссылка на задачу
https://codeforces.com/problemset/problem/1234/D

---

# Разбор

```

Секция "Разбор" пустая → **режим помощи**.

### Пример 2: Режим объяснения (есть разбор)

```markdown
# Ссылка на задачу
https://codeforces.com/problemset/problem/1234/D

---

# Разбор
Динамическое программирование на прямоугольном поле.
Ключевая идея: перебирать клетки в порядке возрастания суммы координат.
Состояния: dp[i][j] = минимальная стоимость достичь ячейки (i, j).
Переходы: dp[i][j] = min(dp[i-1][j], dp[i][j-1]) + cost[i][j].
```

Есть текст в "Разбор" → **режим объяснения**.

## Режим 1: Помощь в решении

### Как работает

1. Claude читает условие по ссылке
2. Показывает краткое условие
3. Молчит и ждёт пока ты спрашиваешь
4. Отвечает только на конкретные вопросы
5. Запоминает ход диалога для итогового разбора

### Философия режима

**Claude не ведёт за руку!**

- Не даёт подсказок проактивно
- Не подтверждает и не опровергает наблюдения без вопроса
- Отвечает только когда спрашиваешь

**Цель:** Ты решаешь сам, Claude - консультант.

### Процесс работы

#### Шаг 1: Вставить ссылку

```markdown
# Ссылка на задачу
https://codeforces.com/problemset/problem/1234/D
```


**Плохие вопросы:**

```

```

## Режим 2: Объяснение разбора

### Как работает

1. Ты вставляешь готовый разбор в PROBLEM.md
2. Claude читает разбор
3. Объясняет решение понятным языком
4. Выделяет ключевые идеи
5. Создаёт детальный editorial (опционально)

### Процесс работы

#### Шаг 1: Найти разбор

**Источники:**
- Официальный editorial на Codeforces
- Комментарии к задаче
- Разборы от других пользователей
- Tutorial на сайте контеста

#### Шаг 2: Вставить в PROBLEM.md

```markdown
# Ссылка на задачу
https://codeforces.com/problemset/problem/1234/D

---

# Разбор
Используем DP по столбцам.
Состояния: положение трубы (верх/низ) в текущем столбце.
Переходы зависят от типа ячейки (1 или 2).
Ячейка "1" - труба только по горизонтали.
Ячейка "2" - труба по вертикали тоже возможна.
База: dp[0][top] = true, dp[0][bottom] = false.
Ответ: можем ли достичь последнего столбца.
```

#### Шаг 3: Запросить объяснение

```
> Читай solution/PROBLEM.md, объясни разбор

Claude: Разбираю решение...

        📖 ОБЪЯСНЕНИЕ

        Суть решения:
        Это динамическое программирование по столбцам.
        На каждом столбце отслеживаем где может быть труба.

        Состояния:
        - dp[col][pos] = можем ли достичь позиции pos
          в столбце col
        - pos: top (верх) или bottom (низ)

        Переходы:
        Зависят от типа ячейки в столбце col:
        1. Тип "1" - только горизонтальные переходы
           - Если верх: труба в верх → следующий верх
           - Если низ: труба в низ → следующий низ

        2. Тип "2" - возможны вертикальные переходы
           - Из верха можем в низ (и наоборот)

        База:
        dp[0][top] = true (начинаем сверху)

        Ответ:
        Проверяем dp[last_col][any] - достигли последнего?

        Сложность: O(n) где n - ширина поля

        Хочешь детальный editorial с анализом ошибок? (да/нет)
```

## Использование без /coach

PROBLEM.md работает **независимо** от `/coach`.

Можно:
```
> Читай solution/PROBLEM.md
```

Без запуска `/coach` - просто разбор задачи.

**Отличие от `/coach` → практика:**
- Без `/coach`: прогресс НЕ фиксируется
- С `/coach`: confidence обновляется, статистика записывается

## Workflow: Решение задачи

### Вариант 1: С тренером

```
1. /coach → 2. ПРАКТИКА
2. Выбрать задачу (своя/рекомендация)
3. Ссылка автоматически в PROBLEM.md
```

## Частые вопросы

### Можно ли работать над несколькими задачами?

**PROBLEM.md - для одной задачи за раз.**

Для нескольких задач:
- Создавай копии: `PROBLEM_1.md`, `PROBLEM_2.md`
- Или используй `/coach` → практика (всё автоматически)

### Что делать после AC?

**Очистить PROBLEM.md** для следующей задачи:

```markdown
# Ссылка на задачу


---

# Разбор

```

Или оставить для справки и создать копию.

### Нужно ли удалять старые editorials?

**Нет!** Editorials - это база знаний.

Храни все разборы в `editorials/`.

Можно вернуться позже для повторения.

### Можно ли вставить разбор на английском?

**Да!** Claude понимает любой язык.

Объяснение будет на русском (по контексту).

### Что если разбор непонятный?

**Попроси объяснить подробнее:**

```
> Объясни секцию "Переходы DP" подробнее
> Не понял как работает база, объясни с примером
> Что такое "обратный переход"?
```

### Влияет ли работа с PROBLEM.md на confidence?

**Только через `/coach`.**

Если работаешь с PROBLEM.md напрямую (без `/coach`):
- Прогресс не фиксируется
- Confidence не меняется

Для фиксации прогресса → используй `/coach` → практика.

## Советы

### При решении

1. **Формулируй наблюдения письменно** - помогает мыслить
2. **Задавай конкретные вопросы** - не "как решать", а "правильно ли что..."
3. **Не спеши к коду** - сначала пойми логику
4. **Проверяй edge cases** - пустой ввод, максимум, минимум

### При изучении разбора

1. **Не просто читай - пойми** - почему именно так
2. **Задавай вопросы** - что непонятно
3. **Реализуй сам** - не копируй код из разбора
4. **Создай editorial** - зафиксируй что пропустил

### После решения

1. **Запиши ключевую идею** - в editorial
2. **Добавь в библиотеку** - если новая техника
3. **Решить похожую задачу** - для закрепления
