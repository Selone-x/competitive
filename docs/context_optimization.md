# Оптимизация контекста для персонального тренера

**Проблема:** При активном использовании персонального тренера профиль пользователя будет расти, что приведет к увеличению потребления токенов и может упереться в лимиты Claude Pro.

**Дата:** 2026-02-03
**Статус:** ✅ Реализовано (2026-02-05)

---

## Анализ проблемы

### Текущая архитектура

```json
// coach/profile.json - единый файл со всем
{
  "version": "1.0",
  "user_info": { ... },                    // ~200 tokens
  "knowledge_assessment": { ... },          // ~300 tokens
  "codeforces_analysis": { ... },          // ~500 tokens
  "training_plan": { ... },                // ~200 tokens
  "session_history": [                     // РАСТЕТ!
    { /* сессия 1 */ },                    // ~150 tokens каждая
    { /* сессия 2 */ },
    // ... сотни сессий
  ],
  "topics_history": { ... }                // ~100-500 tokens
}
```

### Рост со временем

| Период | Сессий | Размер session_history | Общий размер профиля | Токенов на сессию /coach |
|--------|--------|------------------------|----------------------|--------------------------|
| Начало | 0 | 0 KB | ~1.5 KB | ~12-20K |
| 1 месяц | 12 | ~2 KB | ~3.5 KB | ~15-23K |
| 3 месяца | 36 | ~6 KB | ~7.5 KB | ~19-27K |
| 6 месяцев | 72 | ~12 KB | ~13.5 KB | ~25-33K |
| 1 год | 144 | ~24 KB | ~25.5 KB | ~37-45K |
| 2 года | 288 | ~48 KB | ~49.5 KB | ~61-69K |

**Расчет:** 3 сессии в неделю × 4 недели = 12 сессий/месяц

**Токены на сессию включают:**
- SKILL.md (~3,500 tokens)
- Профиль (растет от 1.5K до 25K+)
- Материалы если нужны (~2-5K)
- Диалог (~5-15K input + output)

## Расход токенов vs Claude Pro лимиты

### Текущий сценарий (без оптимизации)

**Месячный расход:**
- 12 сессий/месяц
- Средняя сессия через 6 месяцев: ~25,000 tokens
- **Итого: ~300,000 tokens/месяц**

**Годовой расход:**
- По мере роста профиля средняя сессия увеличивается
- Средняя за год: ~30,000 tokens
- 144 сессии × 30,000 = **~4,300,000 tokens/год**

### Claude Pro лимиты (ориентировочно)

Claude Pro ($20/месяц) имеет rate limiting по сообщениям, а не жесткий лимит токенов:
- **Sonnet 4.5:** обычно 50-100+ сообщений в день (зависит от нагрузки)
- **Opus 4.5:** более ограниченные лимиты
- **Эквивалент:** ~5-10 миллионов токенов/месяц для активного пользователя

**Вывод:** 300K tokens/месяц вполне укладывается в Claude Pro, **НО**:
- Через 1-2 года каждая сессия будет потреблять 40-70K tokens
- Это уже 480K-840K tokens/месяц
- При росте до 5-6 сессий в неделю может стать проблемой

---

## Решение: Оптимизация архитектуры

### Новая структура (гибридный подход)

```
coach/
├── core.json              # Минимум для работы (2-3 KB)
├── stats.json             # Агрегированная статистика (3-5 KB)
├── archive/               # Старые сессии (не загружаются)
│   ├── 2026-01.json
│   └── 2025-12.json
└── sessions/              # Детальные логи (по запросу)
    ├── 2026-02/
    │   ├── 03_CF1444A.md
    │   └── 02_learning_dp.md
    └── 2026-01/
        └── ...
```

### coach/core.json - загружается всегда

```json
{
  "version": "1.0",
  "user_info": {
    "codeforces_handle": "user",
    "preferred_language": "cpp",
    "worked_with_claude": true
  },
  "knowledge_assessment": {
    "topic_confidence": {
      "binary_search": 8,
      "dp": 6,
      // ... 10 тем = 10 чисел
    },
    "weak_topics": ["dp", "graphs"],      // массив
    "strong_topics": ["binary_search"]    // массив
  },
  "training_plan": {
    "current_phase": "intermediate",
    "target_rating": 1800,
    "focus_areas": ["dp", "graphs"],
    "weekly_goals": {
      "problems_per_week": 10,
      "learning_sessions_per_week": 2
    },
    "strategy": "focused"
  },
  "recent_summary": [
    // Только последние 10 сессий в кратком виде
    {
      "date": "2026-02-03",
      "mode": "practice",
      "outcome": "solved",
      "topics": ["dp"],
      "confidence_delta": { "dp": +1 }
    }
    // ... до 10 записей
  ],
  "last_updated": "2026-02-03T15:00:00Z"
}
```

**Размер:** ~2-3 KB независимо от количества сессий ✅

### coach/sessions/ - детальные логи (не загружаются автоматически)

Полные логи сессий в markdown для последующего анализа:

```markdown
# Practice Session: CF 1444A

**Date:** 2026-02-03 16:00
**Duration:** 40 minutes
**Outcome:** ✅ Solved
**Topics:** number_theory, greedy

## Problem
[Ссылка и условие]

## Timeline
- 0-5 min: Понял что нужен делитель p не делящийся на q
- 5-15 min: Пробовал bruteforce - TLE
- 15-25 min: Breakthrough - надо убирать простые множители q из p
- 25-40 min: Реализация и AC

## Key Insights
- Bruteforce O(p) не проходит для p до 10^18
- Достаточно убрать по одной степени каждого простого из q
- Факторизация только q, а не p

## Confidence Changes
- number_theory: 6 → 7
- greedy: 7 → 7
```

**Размер одного лога:** ~1-2 KB
**Использование:** Только когда пользователь явно запрашивает историю

### coach/archive/ - старые сессии (сжатые)

Сессии старше 3 месяцев архивируются:

```json
// coach/archive/2025-12.json
{
  "month": "2025-12",
  "sessions_count": 14,
  "solved": 11,
  "topics_summary": {
    "dp": { "attempts": 5, "solved": 4 },
    "graphs": { "attempts": 4, "solved": 3 }
  },
  "notable_sessions": [
    // Только важные моменты, не все детали
    {
      "date": "2025-12-15",
      "milestone": "Первый раз решил задачу уровня 1600",
      "problem": "CF 1234D"
    }
  ]
}
```

## Преимущества новой архитектуры

### 1. Экономия токенов

| Компонент | Старая архитектура (через год) | Новая архитектура | Экономия |
|-----------|-------------------------------|-------------------|----------|
| Профиль (core.json) | ~25,000 tokens | ~2,500 tokens | **90%** |
| Статистика (stats.json) | Included | ~4,000 tokens | Грузим только при `/coach stats` |
| Детали сессий | Included | 0 tokens | Не грузим автоматически |
| **Итого на сессию /coach** | ~37-45K | ~14-22K | **~50%** |

### 2. Производительность

- **Быстрая загрузка:** только 2-3 KB вместо 25+ KB
- **Меньше парсинга:** не нужно обрабатывать сотни записей session_history
- **Предсказуемый размер:** core.json не растет со временем

### 3. Масштабируемость

- **Работает годами:** даже после 1000+ сессий core.json остается маленьким
- **Архивация:** старые данные доступны, но не загружаются
- **Детали по запросу:** полные логи доступны когда нужны

## Расход токенов с оптимизацией

### Через 1 год (144 сессии)

**Одна сессия /coach:**
- SKILL.md: ~3,500 tokens
- core.json: ~2,500 tokens (не растет!)
- Материалы: ~2,000-5,000 tokens
- Диалог: ~5,000-15,000 tokens
- **Итого: ~13,000-26,000 tokens** (было 37-45K)

**Месячный расход:**
- 12 сессий × ~20,000 tokens = **~240,000 tokens/месяц** (было 300K+)
- **Экономия: ~20-30%**

**Годовой расход:**
- 144 сессии × ~20,000 tokens = **~2,880,000 tokens/год** (было 4.3M)
- **Экономия: ~33%**

### Через 2 года (288 сессий)

**Без оптимизации:**
- Профиль: ~50 KB = ~50,000 tokens
- Сессия: ~62,000 tokens
- Год: ~7,440,000 tokens

**С оптимизацией:**
- Профиль: ~2.5 KB = ~2,500 tokens (фиксировано!)
- Сессия: ~20,000 tokens
- Год: ~2,880,000 tokens
- **Экономия: ~61%**

## Вывод

### Текущая архитектура

✅ **Хватит на первые 6-12 месяцев** активного использования
⚠️ **Может стать проблемой через 1-2 года** при активных тренировках
❌ **Не масштабируется** для долгосрочного использования

### С оптимизацией

✅ **Стабильный расход токенов** независимо от количества сессий
✅ **~50-60% экономии** после года использования
✅ **Масштабируется на годы** без деградации производительности
✅ **Укладывается в Claude Pro** даже при 5-6 сессиях в неделю

## Альтернативные подходы

### 1. Внешняя база данных (SQLite)

**Плюсы:**
- Эффективные запросы
- Индексы для быстрого поиска
- Транзакции

**Минусы:**
- Усложнение архитектуры
- Нужен Python скрипт для работы с БД
- Не читается человеком (JSON проще)

**Вывод:** Избыточно для этого проекта

### 2. OpenClaw как контекст-движок

**Плюсы:**
- Управление сессиями через WebSocket
- Контекст в памяти

**Минусы:**
- Требует запуск отдельного сервиса
- Сложная интеграция с Claude Code CLI
- Overkill для персонального тренера

**Вывод:** Не подходит для CLI архитектуры

### 3. Vector DB для семантического поиска

**Плюсы:**
- Умный поиск похожих сессий
- Рекомендации на основе истории

**Минусы:**
- Очень сложная реализация
- Нужна embedding модель
- Дорого по ресурсам

**Вывод:** Возможно в будущем, но сейчас не нужно

## Метрики для мониторинга

После реализации отслеживать:

1. **Размер профиля**
   ```bash
   ls -lh coach/*.json
   ```

2. **Количество сессий**
   ```bash
   find coach/sessions -type f | wc -l
   ```

3. **Расход токенов** (примерно)
   ```
   (размер core.json в KB) × 1000 = токенов профиля
   ```

4. **Архивированные данные**
   ```bash
   ls -lh coach/archive/
   ```

## Заключение

Проблема роста контекста **реальна** и должна быть решена до того, как пользователи начнут активно тренироваться. Предложенная архитектура с разделением на `core.json` (минимум) и `stats.json` (статистика) обеспечивает:

- **50-60% экономии токенов** после года использования
- **Стабильную производительность** независимо от количества сессий
- **Совместимость с Claude Pro** лимитами на долгие годы
- **Простоту реализации** (JSON файлы, без внешних зависимостей)

Реализация займет ~4-6 часов работы, но обеспечит масштабируемость системы на годы вперед.
