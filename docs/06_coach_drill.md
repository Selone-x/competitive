# Режим drill (набивашки)

## Что такое drill?

Drill - это тренировка мышечной памяти через набивание кода алгоритмов по памяти без подсматривания.

**Цель режима:**
- Натренировать руки набивать код быстро
- Запомнить реализацию алгоритмов наизусть
- Готовиться к контестам (разогрев)
- Выявить пробелы в знании реализаций

**Важно:** Drill не влияет на confidence. Это тренировка рук, а не изучение теории.

## Отличие от обучения

| Обучение | Drill |
|----------|-------|
| Изучение теории | Тренировка рук |
| С материалами | Только по памяти |
| Quiz на понимание | Семантическая проверка кода |
| +2 к confidence | 0 к confidence |
| 15-30 минут | 5-10 минут |

**Аналогия:** Обучение = изучение английского. Drill = скоропечатание на английском.

## Когда использовать?

- Знаешь алгоритм теоретически, но набиваешь медленно
- Перед контестом - разогреть руки
- Регулярно (2-3 раза в неделю) для поддержания мышечной памяти
- После обучения - закрепить реализацию
- Есть свободные 10 минут - быстрая тренировка

### Шаг 2: Показ метаданных (без кода!)

```
📋 МЕТАДАННЫЕ АЛГОРИТМА

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
Название: Dijkstra's Algorithm
Тема: Shortest Path in Weighted Graph
Сложность: O((V + E) log V)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Описание:
Алгоритм поиска кратчайших путей от одной вершины
до всех остальных в графе с неотрицательными весами.

Основные функции/структуры:
1. dijkstra(graph, start) -> vector<int> distances
2. Использует priority_queue для выбора вершины
3. Вектор dist[] для хранения расстояний

Ключевые моменты реализации:
- Инициализация dist[start] = 0, остальные = INF
- Priority queue с парами (dist, vertex)
- Обновление соседей если нашли короче путь
- Посещённые вершины не обрабатываем повторно

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

КОД НЕ ПОКАЗАН - набей по памяти!

Файл для работы:
- C++: solution/cpp/task.cpp
- Python: solution/py/main.py

Набивай код и напиши "готово" когда закончишь.
```

**Что видишь:**
- Название и описание алгоритма
- Сложность
- Сигнатуры функций
- Ключевые моменты реализации (подсказки)

**Что НЕ видишь:**
- Сам код!
- Детали реализации
- Точный синтаксис

### Шаг 3: Набивание кода

**Правила:**
- Набивай по памяти, без подсматривания
- Можно подсмотреть метаданные (ключевые моменты)
- Не обязательно 100% совпадение - важна семантика
- Можно пропустить некоторые детали (комментарии, examples)

### Шаг 4: Семантическая проверка

```
Читаю твой код из solution/cpp/task.cpp...

Проверяю семантику...
```

**Что проверяется:**

1. **Основные структуры** - есть ли нужные функции/классы
2. **Логика алгоритма** - правильная ли последовательность шагов
3. **Ключевые операции** - инициализация, обновление, возврат
4. **Граничные случаи** - обработка пустого входа, особых ситуаций

**Что НЕ проверяется:**

- Точное совпадение имён переменных
- Стиль кода (отступы, пробелы)
- Комментарии
- Примеры использования

### Шаг 5: Показ эталона

```
📖 ЭТАЛОННАЯ РЕАЛИЗАЦИЯ

Вот КОПИРУЕМЫЙ БЛОК из library/cpp/dijkstra.cpp:

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
(показывается код из НАЧАЛО/КОНЕЦ КОПИРУЕМОГО БЛОКА)

vector<int> dijkstra(vector<vector<pair<int,int>>>& graph, int start) {
    int n = graph.size();
    vector<int> dist(n, INF);
    dist[start] = 0;

    priority_queue<pair<int,int>, vector<pair<int,int>>, greater<>> pq;
    pq.push({0, start});

    while (!pq.empty()) {
        auto [d, u] = pq.top();
        pq.pop();

        if (d > dist[u]) continue;

        for (auto [v, w] : graph[u]) {
            if (dist[u] + w < dist[v]) {
                dist[v] = dist[u] + w;
                pq.push({dist[v], v});
            }
        }
    }

    return dist;
}
```

## Рекомендации по использованию

### Как часто делать drill?

**Рекомендуется:**
- 2-3 раза в неделю по 15-20 минут
- 2-3 алгоритма за сессию

**Перед контестом:**
- 30-60 минут за день до контеста
- Набить 5-7 часто используемых алгоритмов

**После изучения новой темы:**
- Сразу после обучения
- Через день для повторения
- Через неделю для закрепления

### Какие темы набивать?

**Приоритет 1: Часто используемые в контестах**
- Binary search
- Two pointers
- DFS/BFS
- Simple DP patterns
- Segment tree (если уровень 1600+)

**Приоритет 2: Твои слабые темы**
- Темы с confidence < 6
- Которые изучал недавно
- Где была ошибка в прошлом контесте

**Приоритет 3: Экзотические алгоритмы**
- Suffix array
- FFT
- Flows
- Только если уровень 2000+

### Как улучшить точность?

**Если точность < 70%:**
1. Повтори теорию (/coach → обучение)
2. Прочитай комментированную версию
3. Набей алгоритм 2-3 раза подряд
4. Реши задачу с использованием этого алгоритма

**Если точность 70-90%:**
- Нормально! Пропущенные детали не критичны
- Обращай внимание на частые пропуски
- Набивай регулярно для поддержания

**Если точность > 90%:**
- Отлично! Алгоритм усвоен
- Drill раз в 2-3 недели для поддержания
- Переходи к следующему алгоритму

### Что делать с пропущенными деталями?

**Частые пропуски:**
- Запиши их отдельно
- Создай памятку (checklist)
- Обращай внимание при следующем drill

**Пример памятки для dijkstra:**
```
☐ Инициализация dist[start] = 0
☐ Priority queue с (distance, vertex)
☐ Проверка if (d > dist[u]) continue
☐ Обновление dist[v] = dist[u] + w
☐ Push в pq только если улучшили
```

## Частые вопросы

### Зачем drill если можно копировать из библиотеки?

**На контесте:**
- Копирование из библиотеки занимает время
- Нужно найти файл, открыть, скопировать нужный блок
- Если набиваешь по памяти - быстрее на 2-3 минуты

**Мышечная память:**
- Руки набивают автоматически
- Не думаешь о синтаксисе
- Мозг свободен для обдумывания решения задачи

**Аналогия:** Как скоропечатание - можешь смотреть на экран, а не на клавиатуру.

### Почему drill не влияет на confidence?

**Drill тренирует руки, а не мозг.**

Confidence = понимание теории и умение применять.
Drill = скорость набивания кода.

**Можно:**
- Знать теорию (confidence 8), но набивать медленно
- Быстро набивать (drill 95%), но не понимать когда применять (confidence 4)

**Для роста confidence:**
- Режим обучения (quiz)
- Режим практики (решение задач)

### Можно ли делать drill на бумаге?

**Да!** Но менее эффективно.

**На бумаге:**
- Тренируешь память алгоритма
- Не тренируешь руки
- Нет семантической проверки

**На клавиатуре:**
- Тренируешь память + руки
- Можешь запустить и проверить
- Claude даёт обратную связь

### Что делать если не помню алгоритм вообще?

**Не подходит для drill!**

Сначала:
1. Изучи тему (`/coach` → обучение)
2. Решить 1-2 задачи (практика)
3. Прочитай реализацию несколько раз
4. Только потом - drill

**Drill для закрепления, а не для изучения.**

### Нужно ли набивать примеры использования?

**Нет.**

В drill набиваешь только:
- Основной алгоритм (функции/классы)
- Ключевую логику

Не набиваешь:
- Комментарии
- Примеры использования (void example())
- Вспомогательные функции (если не критичны)

### Сколько времени должен занимать drill одного алгоритма?

**Зависит от сложности:**

| Алгоритм | Время (минут) |
|----------|---------------|
| Binary search | 2-3 |
| DFS/BFS | 5-7 |
| Dijkstra | 7-10 |
| Segment tree | 10-15 |
| Suffix array | 15-20 |

**Если тратишь больше:**
- Алгоритм не усвоен
- Сначала изучи теорию
- Прочитай реализацию несколько раз
