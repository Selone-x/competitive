# Оптимизация: проверка до √n

## Какую задачу решает

Сократить время факторизации с O(n) до O(√n), что позволяет обрабатывать числа до 10¹² за разумное время.

## Суть

**Ключевая идея:** Если число `n` составное, то у него есть делитель `d ≤ √n`.

**Почему?**

Если `n = a × b` и оба `a, b > √n`, то:
```
n = a × b > √n × √n = n
```
Противоречие! Значит хотя бы один из `a` или `b` ≤ √n.

## Пример

**Число 360:**

√360 ≈ 18.97

Проверяем делители только до 18:
- `2`: находим `2³` (360 → 45 после деления на 8)
- `3`: находим `3²` (45 → 5 после деления на 9)
- `4, 5, ..., 18`: не нужны, потому что:
  - `4 = 2²` - уже учли двойку
  - `5` - проверим, но 5 не делит 45
  - Дальнейшие числа тоже не делят 5

После цикла остается `n = 5 > 1` → это простое число!

Видно: после √360 ≈ 18.97 делители начинают повторяться в обратном порядке.

## Код с оптимизацией

```cpp
map<long long, int> factorize(long long n) {
    map<long long, int> factors;

    // Проверяем только до √n
    for (long long d = 2; d * d <= n; d++) {
        while (n % d == 0) {
            factors[d]++;
            n /= d;
        }
    }

    // ВАЖНО: если n > 1 осталось, это простой делитель > √n
    if (n > 1) {
        factors[n]++;
    }

    return factors;
}
```

**Почему `if (n > 1)`?**

После цикла `n` может быть:
- `1` - все делители нашли
- `простое число > √n` - это последний множитель

**Пример:** `n = 14 = 2 × 7`
- Цикл до √14 ≈ 3.74: находим `2`, получаем `n = 7`
- `7 > 1` и `7` простое → добавляем `factors[7] = 1`

## Сложность

- **До оптимизации:** O(n) - перебор всех чисел от 2 до n
- **После оптимизации:** O(√n) - перебор только до √n

**Разница:**
- `n = 10⁶`: O(n) = 1 000 000 операций vs O(√n) = 1 000 операций
- `n = 10¹²`: O(n) = невозможно vs O(√n) = 1 000 000 операций (реально)

## Когда применять

**Всегда** при факторизации! Это стандартная оптимизация.

Без неё факторизация бесполезна для больших чисел (> 10⁶).
